## 1. 产品概述

### 1.1 产品背景

CalmBar 当前 12 个模块覆盖「散热、电源、输入、识别、清理、启动项、安全」等系统层能力，但在三个高频场景上仍是空白：

1. **音量只能全局调**。macOS 至今没有「每应用音量」：浏览器广告、会议软件、音乐播放器只能共用一个系统音量，用户被迫反复拖动菜单栏音量或在 App 内找设置。
2. **声音只能走默认设备**。开会时希望音乐留在音箱、会议走耳机，系统只能全局切换输出设备，做不到「按 App 分流」。
3. **系统状态看不见**。CalmBar 只显示温度与风扇，用户无法回答「CPU 现在多少、内存是否吃紧、网络是否在跑、磁盘还剩多少」，也收不到持续高负载、内存压力、磁盘不足、低电量等提醒。
4. **录屏要另装软件**。用户经常需要录制一段操作演示、Bug 复现或会议片段，系统截图不覆盖视频，第三方录屏工具又常带水印、订阅或上传。

本项目不是简单堆功能，而是把上述能力接入 CalmBar 已有的「菜单栏控制台 + 偏好设置 + 独立窗口」体系，保持轻量、无感、可恢复的产品气质。

### 1.2 第一性原则分析

> 回到本质：这三个模块在用户按下菜单栏图标的那一刻，真正提供的分别是——**「把声音分给正确的耳朵」**、**「用一眼判断 Mac 是否健康」**、**「把屏幕上的事录下来且不用再装软件」**。

1. **本质需求**
   - 音频：控制粒度从「整机」下沉到「单个 App」，且不牺牲系统稳定性。
   - 监控：把不可见资源消耗变成可比较、可告警的数值。
   - 录屏：把「选择范围 → 开始 → 结束 → 拿到文件」压缩为不超过 3 次操作。
2. **必要条件**
   - 音频：系统提供按进程捕获与重路由的公开 API（Core Audio Process Tap，macOS 14.2+）。
   - 监控：公开内核计数器可读，且采样成本低于被观测收益。
   - 录屏：ScreenCaptureKit 可用，屏幕录制权限可申请，文件写入可原子收尾。
3. **硬约束**
   - 不得引入内核扩展、音频驱动或私有 TCC 绕过。
   - 不得让音频路径产生明显延迟或爆音。
   - 不得在空闲时持续高频采样。
   - 不得让录制文件因崩溃、权限撤销或磁盘写满而损坏。
   - 不得让新入口改变既有面板的视觉语言与操作路径。

### 1.3 产品目标（含可测指标）

| 目标 | 度量口径 |
|------|----------|
| 音频模块空闲开销可忽略 | Instruments 观测：引擎启用但无 App 播放时 CPU < 0.3%，内存 < 20MB |
| 音量调整跟手 | 从拖动滑杆到听感变化 ≤ 100ms；连续拖动无爆音、无丢帧 |
| 路由切换可恢复 | 设备断开后 2s 内完成回退；回退后音频不中断超过 500ms |
| 监控采样不抢资源 | 1s 采样 + 窗口打开时 CPU < 1.5%；窗口关闭后降为 3s；睡眠/锁屏时停止 |
| 告警不轰炸 | 同一类型 30 分钟内最多 1 条；阈值需连续 2 个采样点确认 |
| 录制稳定 | 1080p30 录制 30 分钟：丢帧率 < 1%，音画偏差 < 80ms，CPU < 20%（Apple Silicon） |
| 录制可收尾 | 手动停止后 ≤ 2s 生成可播放文件；异常中断保留 `.partial` 并在下次启动提示 |
| 面板不突兀 | 模块启用/勾选后：新增工具磁贴恰好 8 个（4×2）、守卫卡恰好 6 张（3×2）；面板总高 ≤ 640pt |
| 旧系统可解释 | macOS 14.0–14.1 打开音频设置页时展示明确原因与替代方案，不出现空白或假开关 |

### 1.5 明确不做（Non-goals）

- 不做麦克风增强、降噪、EQ、声卡驱动或虚拟音频设备。
- 不做按窗口粒度调音量（同一 App 的所有窗口共享音量）。
- 不做进程 Kill、端口管理（已由 LaunchManager 承载）。
- 不做录屏时间线剪辑、标注、打码、GIF 导出、分享链接（列为后续版本）。
- 不做云端同步、账号、埋点或远程诊断。
- 不做每应用网络流量统计（成本高、隐私敏感，仅提供整机网络指标）。

## 3. 详细用例规格说明

### UC-A01 启用/停用音频引擎

| 项目 | 内容 |
|------|------|
| **用例编号** | UC-A01 |
| **参与者** | 用户、音频子系统 |
| **优先级** | 高 |
| **前置条件** | 系统为 macOS 14.2 或更高；CalmBar 已运行；用户位于「设置 → 音频控制」或点击面板音频守卫卡 |
| **后置条件** | 引擎运行时可看到 App 列表并调节音量；停用后所有 Tap 与聚合设备被销毁，App 恢复系统默认输出 |

| **业务规则** | BR-01：只有 macOS ≥ 14.2 才允许启用；低版本不显示假开关<br>BR-02：总开关关闭时必须销毁全部进程 Tap 与聚合设备，不得后台残留<br>BR-03：启用属于用户显式动作，默认不自动开启（见 BR-50）<br>BR-04：引擎异常失败采用 3 次/10 分钟熔断，熔断后需用户手动重启 |

### UC-A02 调节每应用音量（含静音与增强）

| 项目 | 内容 |
|------|------|
| **用例编号** | UC-A02 |
| **参与者** | 用户 |
| **优先级** | 高 |
| **前置条件** | 音频引擎运行中；混音窗口已打开或面板音频卡已展开 |
| **后置条件** | 目标 App 的后续音频按新音量渲染；偏好按 Bundle ID 持久化 |
| **基本事件流** | 1. 用户在混音窗口找到目标 App<br>2. 拖动音量滑杆或直接输入百分比<br>3. 系统以 50ms 去抖更新渲染增益<br>4. 滑杆右侧实时显示数值<br>5. 松手后写入偏好 |
| **备选事件流** | 2a. 输入非法值：自动夹到 0–200<br>2b. 目标 App 已退出：条目保留 10 分钟后淡出<br>3a. App 使用独占/受保护音频：条目显示「无法调节」并禁用滑杆<br>4a. 增强超过 150%：数值转为琥珀色并显示软限幅提示 |
| **业务规则** | BR-05：100% 为原始直通；0% 等效静音；大于 100% 为增强<br>BR-06：增强上限默认 150%，可配置到 200%，必须经过软限幅器<br>BR-07：静音保留当前音量值，再次取消静音恢复原值<br>BR-08：音量按 Bundle ID 持久化，同一 App 多进程共享一组值<br>BR-09：同时路由 App 上限默认 6；达到上限后新增路由需用户确认，确认后替换最早的非固定路由<br>BR-10：连续拖动去抖 50ms，禁止每个像素都触发设备属性写入 |

### 4.2 子流程

**A. 音频路由切换**

```
用户选择目标设备
   │
   ├─ 设备存在且可用？
   │     ├─ 否 → 菜单中置灰 + 原因说明（断开/不支持）
   │     └─ 是 → 复用聚合路径？ → 是：直接绑定
   │                         └─ 否：创建聚合（上限 6）
   │
   ├─ 应用路由（只影响该 Bundle ID）
   ├─ 监听 300ms 内是否发生设备变化
   │     ├─ 是 → 防抖后重新绑定
   │     └─ 否 → 完成
   └─ 失败 → 回退上一设备，提示一次
```

**B. 告警触发**

```
采样 → 指标值越过阈值
   │
   ├─ 连续 2 个样本确认？
   │     ├─ 否 → 忽略（尖峰）
   │     └─ 是 → 检查冷却期
   │             ├─ 冷却中 → 仅更新状态
   │             └─ 可发送 → 检查睡眠/锁屏/专注模式
   │                         ├─ 是 → 抑制
   │                         └─ 否 → 发送通知 + 面板胶囊
   └─ 用户点击 → 打开监控窗口并定位卡片
```

**C. 录制异常恢复**

```
录制中异常（崩溃/断电/权限撤销/磁盘满）
   │
   ├─ 进程仍存活 → 立即收尾 → 校验 → 可播放？ → 是：改名完成
   │                                          └─ 否：保留 .partial + 提示
   └─ 进程已崩溃 → 下次启动扫描 .partial
           ├─ 可修复 → 提示「尝试修复」
           ├─ 不可修复 → 提示「移入废纸篓 / 以后处理」
           └─ 用户忽略 → 7 天后不再主动提示
```

### 4.3 状态机

**音频引擎（AudioEngineState）**

| 状态 | 进入条件 | 允许动作 | 退出 |
|------|----------|----------|------|
| idle | 未启用 | 启用 | running / unsupported |
| unsupported | 系统 < 14.2 | 查看说明 | idle |
| starting | 用户启用 | 取消 | running / failed |
| running | 创建成功 | 调音量/路由/停用 | idle / failed |
| failed | 连续失败 3 次 | 重试/停用 | starting / idle |

**录制（RecordingState）**

| 状态 | 进入条件 | 允许动作 | 退出 |
|------|----------|----------|------|
| idle | 初始 | 准备 | preparing |
| preparing | 打开准备面板 | 选择源/取消 | countdown / idle |
| countdown | 确认开始 | 取消 | recording / idle |
| recording | 倒计时结束 | 暂停/停止 | paused / finalizing |
| paused | 用户暂停 | 继续/停止 | recording / finalizing |
| finalizing | 停止或异常 | 等待 | done / failed |
| done | 文件成功 | 打开/显示 | idle |
| failed | 收尾失败 | 查看原因/重试 | idle |

## 5. UI 设计规范

### 5.1 全局融合原则（对应 R-05 / R-06）

1. **不新增一级入口**：只在既有三类容器内扩展——菜单栏 Popover、偏好设置 Tab、独立窗口。
2. **数量恰好填满网格**：工具磁贴 6→8（4×2），守卫卡 5→6（3×2），不产生半行空洞。
3. **组件与尺寸复用**：`FeatureMasterToggleCard`（36pt 图标 / 14pt 标题 / 12 圆角）、`GroupBox`（8pt 内边距）、`ToolTileButton`（10.5pt 字号 / 8 圆角）、`SettingsIconBadge`（24–36pt）。
4. **字号与间距不变**：设置页正文 12.5pt、说明 11.5pt；面板外边距 14pt、区块间距 12pt、网格间距 6pt。
5. **色彩沿用语义**：新增三色与既有色区分，但保持同一饱和度与明度区间；不在面板中出现大面积彩色背景。
6. **状态表达复用**：启用/停用、权限缺失、空数据、异常分别沿用现有绿色胶囊、橙色横幅、灰色空状态、红色错误文案。
7. **默认不打扰**：老用户升级后新增入口默认关闭；新装用户默认开启监控与录屏入口，音频入口默认关闭（BR-45）。
8. **自适应高度**：面板内容高度上限 640pt；超出时先隐藏监控条，再让工具区变为单行横向滚动。

### 6.2 兼容性矩阵

| 能力 | macOS 14.0–14.1 | macOS 14.2–14.x | macOS 15+ |
|------|-----------------|-----------------|-----------|
| 每应用音量 / 路由 | 不支持，明确降级 | 支持 | 支持（需音频捕获授权） |
| 系统监控 | 支持 | 支持 | 支持 |
| GPU 使用率 | Apple Silicon 支持；Intel 不可读则隐藏 | 同左 | 同左 |
| 录屏 | 支持（SCK + 屏幕录制权限） | 支持 | 支持（可能需重启生效/周期提示） |
| 系统声音录制 | 支持 | 支持 | 支持（音频捕获权限） |

- 仅支持 Apple Silicon 与 Intel；无风扇机型温控逻辑不变。
- 所有新模块在虚拟机、远程桌面、无音频设备环境下必须能进入「不可用/空状态」，不得崩溃。

### 6.3 安全与隐私

- 音频流只在内存中经过 Tap 与聚合设备，不落盘、不上传、不记录内容。
- 监控只读取整机计数器；默认不展示进程名（高级开关需用户主动开启）。
- 录制文件只写入用户选定目录；不自动上传、不生成分享链接。
- 权限说明写清「为什么需要」，并标注可关闭的功能；新权限全部 `isRequiredForCore = false`。
- 不申请私有 TCC 权限，不使用私有 API，不安装内核扩展。
- 日志只记录状态码与耗时，不记录 App 内容、音频样本、屏幕截图。

### 6.4 可靠性

- 音频：引擎异常熔断；退出/睡眠/锁屏时释放 Tap 与聚合设备；下次启动按用户上次状态恢复。
- 监控：采样失败保留上一帧并标注延迟；连续失败 5 次自动降频并提示。
- 录屏：`.partial` + 原子改名；崩溃残留扫描；磁盘/权限异常强制收尾。
- 统一 `RecoveryCoordinator` 注册 `cleanup()`，与现有温控/充电恢复动作同域。

| `recorder.openFolder` | 打开录制文件夹 | 录制目录、recordings | 在访达中打开 |

## 8. 易用性设计原则

### 8.1 零配置快速开始

- **音频**：打开混音窗口即可看到正在播放的 App；不要求先选设备、先配置排除项。
- **监控**：启用即显示概览；菜单栏读数与告警全部默认合理，用户无需逐项配置。
- **录屏**：点击磁贴 → 直接「开始录制」；默认全屏、1080p30、系统声音、3 秒倒计时。

### 8.2 用户可见核心配置 ≤ 4

| 模块 | 首屏必须理解的配置 |
|------|--------------------|
| 音频 | 总开关、增强上限、路由开关、设备断开策略（4 项） |
| 监控 | 总开关、采样间隔、菜单栏读数、告警开关（4 项） |
| 录屏 | 总开关、画质、音频来源、保存位置（4 项） |

其余选项收纳在 GroupBox 内，默认折叠视觉权重较低，不阻塞首用。

### 8.3 全链路无主动打扰

- 音频路由切换不弹窗；仅在失败时提示一次。
- 监控告警有冷却与免打扰；睡眠/锁屏/专注模式静默。
- 录屏开始/结束只用一个提示音 + 控制条状态，不弹出模态窗口。
- 崩溃残留文件提示只出现一次。

### 8.4 小白语言规范（术语 → 人话）

| 禁止出现在用户界面 | 替换为 |
|--------------------|--------|
| Process Tap / 进程 Tap | 按应用单独取声 |
| 聚合设备 | 声音汇合路径（仅在高级说明中出现） |
| Core Audio HAL | 系统音频 |
| 软限幅 | 自动压住过高音量 |
| 内存压力 critical | 内存非常紧张 |
| SCStream / AVAssetWriter | 录制引擎（不出现英文） |
| `.partial` | 未完成的录制文件 |

只有「高级设置」与开发者说明中允许保留技术名词。

### 8.5 状态表达简化

- 任何页面同一时刻只显示**一个**主状态：运行中 / 已停用 / 不可用 / 异常。
- 不使用百分比进度条表达「健康度」，只表达实际资源占比。
- 错误文案统一三段式：「发生了什么 → 为什么 → 你可以怎么做」。

### 8.6 一致性检查表

| 准入项 | 规范要求 | 本方案落实 |

## 10. 里程碑与实施顺序（建议）

| 阶段 | 内容 | 风险 |
|------|------|------|
| M1 | 系统监控与告警（纯读取，无音频链路）（2026-11-03 完成，见 Tab 化 PRD §6.5.11；菜单栏文字读数已随 M10 落地，样式项仍归 M5） | 低 |
| M2 | 音频引擎 Spike + 每应用音量 | 高（需先过 §6.5 第 1–4 项） |
| M3 | 每应用输出路由 + 设备回退 | 高（依赖 M2 聚合路径） |
| M4 | 屏幕录制基础链路 + 历史 | 中（依赖权限与收尾验证） |
| M5 | 菜单栏读数、面板布局统一、迁移与回归 | 低 |

> 若 M2 Spike 未通过（例如目标机型路由不稳定），音频模块整体降级为「仅音量、不做路由」，并在设置页如实说明，不强行交付。

## 11. 四维自审与回填记录（prd-reviewer）

### 11.1 开发者可行性

| # | 风险点 | 判定 | 说明与对策 |
|---|--------|------|-------------|
| 1 | Core Audio Process Tap 仅 macOS 14.2+ | 高危 | 已加版本闸门与明确降级（BR-01） |
| 2 | 每应用路由需聚合设备，蓝牙/采样率变化易爆音 | 高危 | 300ms 防抖、设备变化重绑、Spike 验证（BR-14） |
| 3 | 增强 200% 可能损伤听力/失真 | 中危 | 软限幅 + 默认 150% + 琥珀色警示（BR-06） |
| 4 | 受保护/独占音频无法接管 | 中危 | 行内「无法调节」+ 禁用，不静默失败 |
| 5 | GPU 使用率在 Intel 上不可读 | 中危 | 不可读即隐藏（BR-18） |
| 6 | 录屏崩溃导致文件损坏 | 高危 | `.partial` + 原子改名 + 启动扫描（BR-39/41） |
| 7 | 30 分钟长录制音画漂移 | 中危 | 单调时间戳 + 双轨独立写入 + Spike 验证 |

### 11.2 并发场景

- 已给出三套线程模型（§4.5）与 10 条竞态（§4.6），每条均映射到可回填 BR。
- 关键不可逆顺序：音频「停 IO → 销毁 Tap → 释放聚合」；录屏「停流 → 停写入 → 收尾 → 改名」。

### 11.3 描述模糊点（已在正文消解）

| # | 原模糊点 | 回填结果 |
|---|----------|----------|
| 1 | 「音量增强」上限未定义 | BR-06：默认 150%，最大 200%，软限幅 |
| 2 | 「每应用路由」设备断开后行为未定义 | BR-13：三种策略，默认回退系统 |
| 3 | 「菜单栏读数」数量与宽度未定义 | BR-24/26：最多 3 项、140pt 上限 |
| 4 | 「告警」阈值与频率未定义 | BR-27/28/29：连续 2 点、30 分钟冷却、免打扰 |
| 5 | 「录屏」暂停语义未定义 | BR-36/37：暂停不关文件，时间戳修正 |
| 6 | 「UI 不突兀」缺少可验收口径 | §5.1：8 磁贴 / 6 卡 / 640pt 上限 / 复用组件 |

### 11.4 小白用户易用性

- 首用路径：**音频**打开即见正在播放的 App；**监控**默认只看概览；**录屏**一键开始。
- 最高成本低收益项已移除：不做每应用网络统计、不做录屏剪辑、不做麦克风增强。
- 三条最高优先级改进：① 录屏默认沿用上次配置；② 告警提供「一键静音 30 分钟」；③ 音频不可用时直接说明原因与替代方案。

### 11.5 结论

- **可行性**：监控与录屏可基于公开 API 落地；音频依赖 macOS 14.2+，必须先做 Spike，未通过则按 §10 降级交付。
- **并发**：三模块的线程边界与不可逆顺序已明确，竞态均有 BR 兜底。
- **模糊度**：UI 验收口径、阈值、上限、暂停语义已量化。
- **建议下一步**：评审本 PRD → 确认 M2 Spike 机型与系统版本 → 冻结 §7.3 配置键与 §5.2 面板布局后进入开发。
