# 温控安全策略与风扇控制权交接

> 适用范围：`CalmBarKit/SafetyPolicy.swift`、`CalmBar/Thermal/ThermalMonitor.swift`、
> `CalmBar/Services/FanService.swift`、`CalmBarHelper`。
> 目标：在过温时**先加码散热**，只有确实无法继续安全控制时才把风扇交还系统。

## 1. 档位与动作

主温度取 `SensorCatalog` 中 `isPrimary` 传感器的最大值（Apple Silicon 为 `Tp*` / `Tg*` 结温）。

| 温度区间（Apple Silicon） | 温度区间（Intel） | 档位 | 动作 | 写入 |
| --- | --- | --- | --- | --- |
| < 75°C | < 75°C | `none` | 按预设曲线 / 手动值 | 是 |
| 75–84°C | 75–84°C | `low` | 转速下限 45% | 是 |
| 85–89°C | 85–89°C | `high` | 转速下限 75% | 是 |
| 90–104°C | 90–97°C | `emergency` | 转速下限 95% | 是 |
| ≥ 105°C | ≥ 98°C | `critical` | 转速下限 **100%**，控制权仍在 CalmBar | 是 |
| 持续 ≥ 110°C（30s） | 持续 ≥ 102°C（30s） | 硬限释放 | 交还系统自动控制 | 写 `auto` 后停止 |

- 阈值来自 `ThermalSafetyDefaults`：运行期通过 `sysctlbyname("hw.optional.arm64")` 判断平台，Rosetta 下同样成立。
- 所有档位均带 3°C 滞回，回落到 `阈值 - 3` 才降档。
- 旧版本在 98°C 就 `restoreAuto`，会把「强制 100%」换回系统曲线，可能出现温度越高、转速反而下降的非单调行为；现改为只有硬限持续超限才释放。

## 2. 交还系统的两个条件

1. **温度硬限**：`maxTemp >= releaseTemp` 连续保持 `releaseHoldSeconds`（默认 30s）。单次尖峰只触发 `critical` 的 100% 强制散热，不释放控制权；温度回落到 `releaseTemp - hysteresis` 以下自动重新接管。
2. **连续写入失败**：SMC / Helper 写入连续失败 3 次（每次最长等待 8s，覆盖联动双风扇最坏 FTST 解锁；恢复自动控制为 4s），避免无限重试。Helper 恢复可用后自动重新接管；切换风扇模式视为显式重试。

交还动作本身也带错误处理：`FanService.restoreAuto` 在 Helper 不可用时不再静默返回，而是抛出 `helperUnavailable`。
`ThermalMonitor.releaseControl` 会先等待在途转速写入结束（避免 `auto` 被旧的手动写入覆盖），
再执行恢复，并把失败原因追加到提示中（「恢复系统自动控制失败……风扇可能停留在最后转速」）。
`isControlHandoffConfirmed` 表示交还是否真正写入成功，界面据此显示「已交还系统」或「写入已暂停」。
Helper 恢复可用时会补一次交还写入。

## 3. 控制权与硬限的解除规则

- 只有以下显式操作会清除释放状态并重置硬限计时：
  - 温控卡片 / 设置页的「重新接管」；
  - 命令面板「风扇全速运转」（`forceFullSpeed`）；
  - 将风扇模式切换为「自动」（系统本就接管，释放状态无意义）；
  - 写入失败释放后再次切换模式（视为显式重试）。
- 普通滑杆编辑**不会**清除温度硬限释放或重置 30s 计时，避免通过界面操作无限延后安全交接。
- 温度回落到 `releaseTemp - hysteresis` 以下时自动重新接管。

释放期间 `ThermalMonitor.controlReleaseCause` / `controlReleaseReason` 非空，面板顶栏显示「已交还系统」，
温控卡片提供「重新接管」按钮；滑杆显示真实转速而不是用户目标值。

## 4. 紧急全速命令

「风扇全速运转」走 `ThermalMonitor.forceFullSpeed()`：清除交接状态、重置硬限计时、把（联动或独立）目标设为 100% 并立即写入。用户显式指令优先于自动交接，因此不会在高温时变成空操作。

## 5. 双风扇联动 / 独立调速

- `AppSettings.dualFanLinked` 为真（默认）或只有一个风扇：`FanService.setFanFractions([fraction])` → `setLinkedFraction`。
- 为假且有两个风扇：按索引分别调用 `FanController.setIndependentFraction`（Helper 侧为 `setFanFraction(_:fraction:)`，协议版本 5）。
- 风扇数量以启动时探测的 `FanCapability.fanCount` 为准，不依赖可能瞬时为空的 `fanSnapshots`。
- 安全下限在独立模式下对每个风扇分别取 `max(用户值, floor)`。
- UI 仅在检测到双风扇时展示联动开关；独立模式（未联动 + 自定义）隐藏统一滑杆，改为两个风扇各自的滑杆。
  自动/智能模式下统一滑杆仍然可见，未联动时会同时写入两个风扇，避免拖动值被丢弃。

## 6. Helper 退出与在途写入

- 写入调用带 8s 超时（`FanService.maxWriteDuration`，覆盖联动双风扇最坏 FTST 解锁），恢复自动控制为 4s；
  超时抛 `ServiceError.timeout` 并计入连续失败，避免 `isWriteInFlight` 因 XPC 回复丢失而永久卡死。
- Helper 侧 FTST 解锁窗口为 3s（`FanController.ftstUnlockTimeout`），与应用超时保持同一套常量，避免应用先于 Helper 超时。
- Helper 收到 SIGINT / SIGTERM 时通过 `DispatchSourceSignal` 在主队列先执行 `restoreSystemControl`，
  再退出，避免手动转速残留在 SMC。
- 最后一个 XPC 连接断开时 Helper 仍会恢复自动控制（既有行为）。
