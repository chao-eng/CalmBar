# CalmBar 无风扇机型适配方案（Fanless Mac）

> 目标：让 MacBook Air（M1/M2/M3/M4）、MacBook 12" 等**纯被动散热、无内置风扇**的机型，在安装 CalmBar 后获得正确、无误导的体验 —— 温控模块自动退化为「纯温度监控模式」，彻底隐藏风扇调速相关控件与命令，同时不影响有风扇机型（MacBook Pro / Mac mini / iMac 等）的既有功能。

---

## 1. 背景与现状问题

### 1.1 现状

当前 `ThermalMonitor` 只要成功打开 AppleSMC 驱动即认为温控可用，代码中**不存在「本机有没有风扇」这一概念**，所有风扇逻辑都以“有风扇”为前提：

- `CalmBarKit/FanController.swift` 通过 `FNum` 读取风扇数量；无风扇机型该键不存在或读数为 0。
- `CalmBar/Thermal/ThermalMonitor.swift` 的 `fanSnapshots` 在无风扇机型上恒为空数组，但 `isSMCConnected` 仍为 `true`。
- 特权助手（LaunchDaemon）被声明为硬件温控的 **required** 权限（`Features/ThermalFeature.swift:9-15`），而无风扇机型根本不需要写 SMC。

### 1.2 由此产生的具体问题

| # | 位置 | 无风扇机型上的表现 | 严重度 |
| --- | --- | --- | --- |
| 1 | `UI/PopoverContentView.swift:268-277` | 因 `fanSnapshots.first` 为空，第三个仪表位会**无条件回退显示“电池温度”**，即使电池无温度读数，界面存在误导 | 高 |
| 2 | `UI/PopoverContentView.swift:335` | RPM 读数 else 分支**硬编码展示 “3,060 RPM”**，被动散热机型上显示一个并不存在的转速 | 高 |

## 2. 设计目标与决策

1. **总开关退化为「纯温度监控模式」**（已与需求方确认）：无风扇机型上仍可开关温度/传感器监听、菜单栏温度显示与过温视觉提醒，但**不再暴露任何风扇转速控制**。
2. **能力自适应而非机型硬编码**：以 SMC 实时探测 `FNum` 为准（`hw.model` 仅作日志与兜底参考），有风扇机型行为零变化，避免误伤双风扇/单风扇设备。
3. **不误报、不诱导**：隐藏特权助手激活入口、风扇模式、转速读数与联动控件；文案明确提示“本机为被动散热”。
4. **最小侵入**：保持现有 `Feature / Command / Recovery / Permission` 平台化架构，通过新增“硬件能力”维度做条件门控。

---

## 3. 核心设计：引入 `FanCapability` 硬件能力

在 `CalmBarKit` 层定义只读的硬件能力描述，作为整个功能降级的**单一事实来源**。

### 3.1 新增类型（`CalmBarKit/FanModels.swift`）

```swift
/// 风扇硬件能力
public enum FanCapability: Sendable, Equatable {
    case unknown          // SMC 尚未探测或探测失败
    case fanless          // 已确认无风扇（被动散热）
    case hasFans(Int)     // 有 N 个风扇
}

extension FanCapability {
    public var isFanless: Bool {
        if case .fanless = self { return true }
        return false
    }
    public var fanCount: Int {
        if case .hasFans(let n) = self { return n }
        return 0
    }
    public var supportsFanControl: Bool { !isFanless }
}
```

### 3.2 探测逻辑（`CalmBarKit/FanController.swift`）

在 `FanController.init` 中完成一次性探测并缓存，将结果并入现有 `SMCHardwareConfig`：

```swift
public static func detectCapability(connection: SMCConnection) -> FanCapability {
    // FNum 键缺失 / 读取失败 -> .unknown（无法确认，交由上层按不可用处理，
    // 不与 .fanless 混淆，避免 SMC 暂时不可读时误判）
    guard connection.keyExists(SMCFanKey.count),
          let (bytes, _) = try? connection.readKey(SMCFanKey.count) else {
        return .unknown
    }
    let n = Int(SMCDataFormat.uint8(from: bytes))
    return n > 0 ? .hasFans(n) : .fanless
}
```

- `fanCount()`、`allFans()` 保持原行为，但新增的能力位 `capability` 供上层直接判断，避免每次 `allFans()` 抛错。
- `SMCHardwareConfig` 增加 `let capability: FanCapability` 字段（带默认值 `.unknown`，保证可解码兼容）。
- 所有写风扇的入口（`setLinkedFraction` / `setIndependentFraction` / `setLinkedRPM` / `setAuto` / `restoreSystemControl`）内部加 `guard capability.supportsFanControl else { return }` 静默短路，从库层面杜绝写操作。

> 说明：`hw.model`（如 `Mac14,2`）可写入日志用于诊断，但不作为判定依据，避免列表维护滞后。

## 4. 各层适配改动

### 4.1 `Thermal/ThermalMonitor.swift`（状态源）

- 新增发布属性 `@Published public private(set) var fanCapability: FanCapability = .unknown`。
- `setupController()` 成功后由 `controller.capability` 赋值；SMC 连接失败时置 `.unknown`。
- 派生便捷状态供 UI 订阅：
  - `public var isFanless: Bool { fanCapability.isFanless }`
  - `public var supportsFanControl: Bool { isSMCConnected && fanCapability.supportsFanControl }`
- **门控控制流**：
  - `applyCurrentMode()`：`guard supportsFanControl else { return }`（风扇模式切换依然允许，但只更新 `AppSettings`，不触发任何写操作）。
  - `restoreSystemControl()`：`guard supportsFanControl`，无风扇时直接返回。
  - `isFanControlAuthorized`：无风扇机型恒为 `false` 并**不参与 Feature 状态判断**（见 4.2）。
- **安全策略语义调整**：无风扇时 `SafetyPolicy.evaluate` 结果仅用于驱动“过温提醒徽标”（头部火焰提示、Dashboard 高亮），不再产生转速下限或 `restoreAuto` 写入。即 `currentSafetyAction` 在有风扇时维持原语义；无风扇时只取 `warning/critical` 档用于 UI 提醒。

### 4.2 `Features/ThermalFeature.swift`（Feature 状态机）

| 场景 | SMC 已连接 + 有风扇 | SMC 已连接 + 无风扇 | SMC 不可用 |
| --- | --- | --- | --- |
| state | `running`（未授权时为 `degraded`） | `running`（纯监控，无需授权） | `unavailable/failed` |
| requiredPermissions | `[.privilegedHelper]` | `[]`（温度读取无需 root） | — |
| commands | 保留全部 | 仅保留「查看实时温度」类命令 | — |

实现要点：

```swift
public var requiredPermissions: [FeaturePermissionRequirement] {
    // 无风扇机型读温度无需特权助手
    guard monitor.supportsFanControl else { return [] }
    return [FeaturePermissionRequirement(type: .privilegedHelper, level: .required,
            reason: "...")]
}

public var commands: [FeatureCommand] {
    guard monitor.supportsFanControl else { return [] } // 风扇命令整体不下发
    return [ /* 现有 restoreAuto / fanFull */ ]
}
```

### 4.3 `Commands/CommandCenter.swift`（命令注册）

- `registerFeatureCommands` 遍历各 Feature 的 `commands`，ThermalFeature 在无风扇时返回空数组，命令面板自动不出现「风扇全速运转」。
- 兜底防御：若旧版本残留的 `thermal.fanFull` 被执行，`run` 闭包内先判 `guard ThermalMonitor.shared.supportsFanControl else { return .failure("当前机型为被动散热，无风扇可控制") }`。

### 4.4 `UI/PopoverContentView.swift`（控制中心）

- 仪表区 3 槽改为按能力渲染：CPU / GPU 恒显；第三槽 = `hasFans ? 风扇仪表 : (batteryTemp > 0 ? 电池仪表 : 省略)`；移除“无风扇即显示电池”的回退误导。双风扇机器仍显示两枚风扇仪表。
- `fanControlSection` 整体替换为条件分支：
  - `supportsFanControl` → 现状不变；
  - `isFanless && thermalEnabled` → 展示轻量「纯温度监控」卡片：图标 + “本机无内置风扇（被动散热），已仅保留温度监控与过温提醒”，不出现三档 Picker / 滑杆 / RPM。
  - `!thermalEnabled` → 现状置灰逻辑不变。
- 顶栏状态徽标：`settings.thermalEnabled && thermal.isFanless` 时显示「温度监控」而非暗示风扇策略的文案。
- RPM 读数硬编码 “3,060 RPM”（现 335 行 else 分支）随风扇区块一并移除。

### 4.5 `UI/Settings/Tabs/ThermalSettingsTab.swift`（偏好设置）

- `FeatureMasterToggleCard`：
  - 标题保留「硬件温控与风扇调控引擎」→ 无风扇时改为「硬件温度监控」；
  - `activeSubtitle` 不再拼接 `fanPreset.titleZH`，无风扇时提示“已激活 · 正在持续监听温度传感器（无风扇被动散热机型）”。
- 「特权驱动与控制权限」GroupBox：`supportsFanControl` 为 false 时不渲染，替换为只读提示行：“当前机型无内置风扇，温度读取为只读操作，无需安装特权助手”。
- 「温控调控模式与曲线参数」GroupBox：`supportsFanControl` 为 false 时整组隐藏。
- 「实时传感器读数」GroupBox：保留不变（对无风扇用户这正是核心价值）。
- `Picker` 的 `FanPreset` 在无风扇机型上锁定为 `.auto` 语义即可（写操作已短路，无需额外强转）。

### 4.6 `UI/Dashboard/DashboardViewModel.swift`

- 新增镜像 `@Published private(set) var fanCapability` 与 `isFanless`，订阅 `ThermalMonitor`，供 Dashboard 磁贴/控制中心只读引用（避免各 View 各自持有 ThermalMonitor 强引用判断）。

### 4.7 `UI/StatusBarManager.swift` 与菜单栏温度

- 无改动。菜单栏温度展示依赖 `primaryTemp`，无风扇机型天然可用，且是重要卖点。

### 4.8 `Recovery/RecoveryCoordinator.swift` 与 `Core/SystemEventCoordinator.swift`

- 调用的 `ThermalMonitor.restoreSystemControl()` 因 4.1 门控自动跳过写入，无需逐点改动，但可顺手在注释中说明。
- `CalmBarHelperMain.swift` 的断连恢复（`listener(_:shouldAcceptNewConnection:)` 里 `restoreSystemControl()`）同理受库层 guard 保护。

### 4.9 `PermissionManager.swift` 与权限中心机型化文案

- 功能层面已落实：`.thermal` 的 `defaultRequirements` 按 `ThermalMonitor.requiresHelperForThermal` 门控，无风扇机型返回 `[]`（不再声明特权助手）。
- 新增 MainActor 动态方法 `purposeDescription(for:)`：无风扇机型上 `.privilegedHelper` 的用途说明改写为“80% 充电上限与适配器旁路供电、应用去隔离与自签名修复；当前机型无内置风扇（被动散热），硬件温度读取为只读 SMC 操作，无需风扇调速”，不再引用风扇相关操作。
- `PermissionCenterView` 通过该方法取用途文案；无风扇机型特有关联功能标签自动剔除「硬件温控」（`affectedFeatures` 随 requirements 联动），特权助手“💡 提示”增加“不涉及风扇调速”说明。
- `DashboardViewModel` 的“特权助手未激活（温控与充电受限）”消息改为无风扇机型显示“（充电保护与应用去隔离受限）”。
